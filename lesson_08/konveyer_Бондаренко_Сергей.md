## Письмо 1. Ревью конвейеров

### 1. Выручка доставленных заказов от ноутбуков.

- Решение: есть ошибка — сумма по полю заказа после $unwind — итог повторён в каждой позиции — верно
- Комментарий: После $unwind один заказ повторяется для каждой позиции. Суммирование $total считает всю стоимость заказа за каждый ноутбук и включает другие товары. Нужно суммировать стоимость позиции: $items.price × $items.qty.
- Исправленный конвейер:

```js
[{ $match: { status: "доставлен" } }, { $unwind: "$items" }, { $match: { "items.category": "ноутбуки" } }, { $group: { _id: null, revenue: { $sum: { $multiply: ["$items.price", "$items.qty"] } } } }]
```

### 2. Сколько заказов в пути в каждом городе.

- Решение: есть ошибка — $project перед стадией, которой нужно отброшенное поле — верно
- Комментарий: На первом шаге $project удаляет status. Поэтому следующий $match сравнивает отсутствующее поле и отбрасывает все 120 заказов. Нужно сначала отобрать status: "в пути", а потом оставить нужные поля.
- Исправленный конвейер:

```js
[{ $match: { status: "в пути" } }, { $project: { number: 1, delivery: 1 } }, { $group: { _id: "$delivery.city", orders: { $sum: 1 } } }, { $sort: { _id: 1 } }]
```

### 3. Номер первого по дате заказа каждого покупателя из трёх: c-007, c-011, c-018.

- Решение: конвейер верный — неверно
- Комментарий: После отбора трёх покупателей $first берёт первый встретившийся заказ каждого; по результату это 2026-0002, 2026-0006 и 2026-0001. Финальная сортировка выводит покупателей по их идентификаторам.

### 4. Пять самых дорогих доставленных заказов.

- Решение: есть ошибка — стадии стоят не в том порядке: $limit срабатывает раньше отбора — верно
- Комментарий: $limit оставляет пять самых дорогих заказов вообще, а $match затем выбрасывает недоставленные — остаются только два. Для пяти самых дорогих доставленных нужно сначала отфильтровать status, затем отсортировать total и ограничить пятью.
- Исправленный конвейер:

```js
[{ $match: { status: "доставлен" } }, { $sort: { total: -1 } }, { $limit: 5 }, { $project: { _id: 0, number: 1, total: 1 } }]
```

### 5. Выручка доставленных заказов по способам оплаты.

- Решение: есть ошибка — путь к полю записан без знака $ — верно
- Комментарий: В $group значение _id: "payment.method" — это одна и та же строка для всех заказов, а не чтение поля. Нужен путь с $: _id: "$payment.method". Общая сумма верна, но разбивка по способам оплаты потеряна.
- Исправленный конвейер:

```js
[{ $match: { status: "доставлен" } }, { $group: { _id: "$payment.method", revenue: { $sum: "$total" } } }, { $sort: { _id: 1 } }]
```

### 6. Сколько штук смартфонов продано в доставленных заказах.

- Решение: есть ошибка — условие на элемент массива проверено до $unwind — проходят заказы целиком — верно
- Комментарий: Первый $match проверяет только наличие смартфона в массиве и пропускает заказ целиком. После $unwind в сумму попадают количества всех товаров такого заказа. Нужно отобрать items.category: "смартфоны" уже после разворачивания массива.
- Исправленный конвейер:

```js
[{ $match: { status: "доставлен" } }, { $unwind: "$items" }, { $match: { "items.category": "смартфоны" } }, { $group: { _id: null, qty: { $sum: "$items.qty" } } }]
```

### 7. Средний чек доставленных заказов в каждом городе, округлённый до рубля, по убыванию.

- Решение: конвейер верный — верно
- Комментарий: Сначала остаются только доставленные заказы, затем $group считает средний total по delivery.city. $project округляет avg, сохраняя _id с городом, а $sort ставит самые большие значения первыми. Новосибирск действительно первый: 149 226.

### 8. Три самых продаваемых по штукам товара в доставленных заказах.

- Решение: конвейер верный — верно
- Комментарий: Конвейер считает только доставленные заказы. После $unwind каждая позиция учитывается отдельно; $group суммирует qty по названию товара, $sort упорядочивает по количеству и разрешает равенства по названию, $limit оставляет три лидера. Получилось 20, 19 и 18 штук.

## Письмо 4. Свои конвейеры

### 1. Доставленные заказы по способу доставки: _id — способ (delivery.type), orders — число заказов, revenue — выручка. По убыванию revenue.

```js
db.orders.aggregate([{ $match: { status: "доставлен" } }, { $group: { _id: "$delivery.type", orders: { $sum: 1 }, revenue: { $sum: "$total" } } }, { $sort: { revenue: -1 } }])
```

- Результат совпадает с нужным, запусков: 1

### 2. Коллекция products. Средняя цена товаров каждой категории, округлённая до рубля: _id — категория, avg — средняя цена. По возрастанию avg.

```js
db.products.aggregate([{ $group: { _id: "$category", avg: { $avg: "$price" } } }, { $project: { avg: { $round: ["$avg", 0] } } }, { $sort: { avg: 1 } }])
```

- Результат совпадает с нужным, запусков: 1

### 3. Покупатели, у которых сумма доставленных заказов больше 400 000: _id — customer_id, spent — сумма. По убыванию spent.

```js
db.orders.aggregate([{ $match: { status: "доставлен" } }, { $group: { _id: "$customer_id", spent: { $sum: "$total" } } }, { $match: { spent: { $gt: 400000 } } }, { $sort: { spent: -1 } }])
```

- Результат совпадает с нужным, запусков: 1

### 4. Для каждого города — массив номеров отменённых заказов по возрастанию номера: _id — город, numbers — массив. Города по алфавиту.

db.orders.aggregate([{ $match: { status: "отменён" } }, { $sort: { number: 1 } }, { $group: { _id: "$delivery.city", numbers: { $push: "$number" } } }, { $sort: { _id: 1 } }])

### 5. Одним запросом по доставленным заказам: в поле total — массив из одного документа { orders: число заказов }, в поле top — три товара с наибольшим числом штук (_id — название, qty — штуки), по убыванию qty, при равенстве — по названию.
